# Trajectron++ 路侧轨迹预测实验报告

> 实验时间: 2026-03-04 ~ 2026-03-07
> 模型: Trajectron++ (Salzmann et al., ECCV 2020)
> 数据集: THICV 天津路侧感知数据集

---

## 1. Introduction & Motivation

### 1.1 研究背景

轨迹预测是自动驾驶和智能交通系统的核心任务。现有主流方法 (Trajectron++, Social-LSTM, AgentFormer 等) 均基于**车载视角** (ego-centric) 数据集 (nuScenes, Argoverse, ETH/UCY) 进行开发与验证。然而，随着车路协同 (V2X) 和智慧交通基础设施的发展，**路侧感知** (infrastructure-based) 视角日益重要。

### 1.2 为什么选择 Trajectron++ + 路侧数据

本实验的核心动机是验证：**车载视角下成熟的轨迹预测模型，能否有效迁移到路侧感知场景？**

选择 Trajectron++ 的原因：
- **多类目标建模**: 原生支持 VEHICLE 和 PEDESTRIAN 的异构动力学模型 (Unicycle / SingleIntegrator)，适合路侧场景中多类交通参与者共存的特点
- **图结构交互**: 基于场景图 (Scene Graph) 建模 agent 间交互，与路侧视角下的全局态势感知天然契合
- **概率预测**: CVAE 框架输出多模态轨迹分布，可直接服务于下游安全评估 (TTC/PET)
- **可复现性**: 开源代码成熟，便于迁移适配

### 1.3 路侧 vs 车载视角的核心差异

| 维度 | 车载视角 (nuScenes) | 路侧视角 (THICV) |
|------|-------------------|-----------------|
| **坐标系** | 相对自车，范围小 (~50m) | 全局坐标，跨度数百米 |
| **观测范围** | 前方/周围有限区域 | 固定区域全覆盖 (路口全景) |
| **遮挡** | 严重 (自车视角盲区) | 较少 (高处俯视) |
| **目标类型** | 以周围车辆为主 | 车辆 + 行人 + 非机动车混合 |
| **场景特点** | 行驶中的动态场景 | 包含排队、停车等静态密集场景 |
| **数据频率** | 2Hz (标注) | ~7-8Hz (LiDAR), 降采样到 2Hz |

这些差异意味着直接将车载模型应用于路侧数据会面临**坐标尺度不匹配、标准化参数失效**等问题，本实验正是围绕这些问题展开。

### 1.4 与课题的关系

本实验属于课题"基于路侧感知的交通安全态势评估"的核心技术模块：

```
路侧 LiDAR 感知 → 目标检测/追踪 → [轨迹预测 (本实验)] → 安全指标计算 (TTC/PET) → 态势评估
```

路侧视角的独特价值在于：
1. **覆盖所有交通参与者** — 不局限于自车周围，可分析整个路口的车-车、车-人、人-人交互
2. **无自车运动干扰** — 坐标系固定，轨迹预测无需处理自车运动补偿
3. **安全评估的全局性** — 可计算任意 agent 对之间的 TTC/PET，而非仅限于自车相关的风险

## 2. Dataset Description

### 2.1 THICV 数据集概况

THICV (Tsinghua Highway Intersection Connected Vehicle) 天津路侧数据集来自部署在交叉路口的路侧 LiDAR 感知系统，包含 3D 目标检测和多目标追踪结果。

**基本信息**：

| 属性 | 值 |
|------|-----|
| 传感器 | 路侧 LiDAR |
| 原始频率 | ~7-8 Hz |
| 场景数量 | ~90 个场景段 |
| 标注格式 | 逐帧 JSON (含位置、尺寸、航向角) |
| 标注版本 | 原始标注 (`ori_labels`) + 插值平滑标注 (`interpolation_labels`) |
| 坐标系 | 全局坐标 (路口固定参考系) |

**每帧标注内容**：
```json
{
  "timestamp": 1648174256000,
  "object": [
    {"id": 42, "label": "Car", "x": 105.3, "y": -42.1, "z": 1.2,
     "yaw": 1.57, "length": 4.5, "width": 1.8, "height": 1.5}
  ]
}
```

### 2.2 数据统计

经过预处理后的数据集规模 (使用 `interpolation_labels`):

| 指标 | Train | Val | Test |
|------|-------|-----|------|
| 场景数 | 61 | 14 | 14 |
| VEHICLE 节点数 | 3,792 | 842 | 876 |
| PEDESTRIAN 节点数 | 1,490 | 291 | 277 |
| 轨迹长度 (中位数) | 31 帧 (15.5s) | 28 帧 (14s) | 28 帧 (14s) |
| 轨迹长度 (最大) | 88 帧 (44s) | 46 帧 (23s) | 46 帧 (23s) |

**位置分布 (中心化后)**：

| 统计量 | X (m) | Y (m) |
|--------|-------|-------|
| 标准差 | 82.4 | 40.2 |
| 范围 | -372 ~ 307 | -265 ~ 236 |

**速度分布**：

| 统计量 | 值 |
|--------|-----|
| 均值 | 3.81 m/s |
| 95分位 | 14.63 m/s |
| 最大值 | 30.0 m/s (clipping 后) |

### 2.3 类别映射

路侧数据包含丰富的目标类别，需映射到 Trajectron++ 支持的两类：

| Trajectron++ 类型 | 原始标签 | 动力学模型 |
|------------------|---------|-----------|
| **VEHICLE** | Car, SUV, Bus, Truck, Van, Trailer, Engineering_vehicle, Fire_engine, Vehicle_else, Huge_vehicle | Unicycle |
| **PEDESTRIAN** | Pedestrian, Person, Cyclist, Bicycle, Motorcycle, Tricycle, Non_motor_rider, Motor_rider, Other_rider | SingleIntegrator |

> **设计选择**: 骑行者和非机动车 (电瓶车、摩托车) 被合并到 PEDESTRIAN 类别。原因是这些目标缺乏可靠的航向角标注，其运动模式更适合无航向约束的 SingleIntegrator 动力学模型。这也解释了 PEDESTRIAN 类别中存在 5-15 m/s 高速样本的现象。

## 3. Data Processing Pipeline

### 3.1 流程概览

```
原始 JSON 帧序列
  ↓ 读取 + 时间戳排序
逐场景合并目标轨迹 (按 tracking ID)
  ↓ 重采样 (7-8Hz → 2Hz, dt=0.5s)
过滤短轨迹 (min_track_length=4, 即 2 秒)
  ↓ 场景中心化 (减去场景均值)
计算导数 (velocity, acceleration, heading)
  ↓ Norm-based clipping
标准化 (standardization)
  ↓ 数据增强 (24 个旋转角度, 0°~360° 步长 15°)
Trajectron++ Environment 对象
  ↓ Train/Val/Test 划分 (70%/15%/15%)
输出 .pkl 文件
```

### 3.2 关键参数

| 参数 | 值 | 说明 |
|------|-----|------|
| `label_type` | `interpolation` | 使用插值平滑标注 |
| `resample_dt` | 0.5s | 与 nuScenes 对齐 (2Hz) |
| `min_track_length` | 4 帧 | 最少 2 秒有效轨迹 |
| `augment` | 0°~360°, 步长 15° | 24 个旋转增强 |

### 3.3 坐标中心化

每个场景的所有目标坐标减去场景均值，将坐标原点移至场景中心：
```python
x_centered = x - x_mean_of_scene
y_centered = y - y_mean_of_scene
```
这一步将全局坐标 (跨度数百米) 转换为以场景为中心的相对坐标，降低了位置值的绝对大小，但**标准差仍然高达 80m**。

### 3.4 标准化参数 (关键适配点)

从 nuScenes 迁移到路侧数据时，标准化参数需要重新设定：

| 参数 | nuScenes 原值 | 路侧数据适配值 | 说明 |
|------|-------------|--------------|------|
| PEDESTRIAN position x std | 1 | **80** | 路侧全局坐标跨度大 |
| PEDESTRIAN position y std | 1 | **40** | 同上 |
| VEHICLE position x std | 80 | 120 | 路侧跨度更大 |
| VEHICLE position y std | 80 | 60 | 同上 |
| 速度/加速度 clipping | 分量级 | **Norm 级** | 消除 √2 放大 |

## 4. Model Configuration

### 4.1 网络架构

Trajectron++ 采用 CVAE (Conditional Variational Autoencoder) 架构，结合 RNN 编码器-解码器和场景图注意力机制。

| 参数 | 值 |
|------|-----|
| 预测时域 | 6 步 (3.0 秒) |
| 最大历史长度 | 8 步 (4.0 秒) |
| 编码器 RNN dim | 32 (history/future/edge) |
| 解码器 RNN dim | 128 |
| GMM 分量数 | 1 |
| 交互建模 | 动态场景图 + 注意力机制 |

### 4.2 动力学模型

| 类型 | 动力学 | 状态变量 |
|------|--------|---------|
| VEHICLE | Unicycle | position(x,y), velocity(x,y), acceleration(x,y), heading(°,d°) |
| PEDESTRIAN | SingleIntegrator | position(x,y), velocity(x,y), acceleration(x,y) |

### 4.3 训练配置

| 参数 | 值 |
|------|-----|
| Batch size | 4096 |
| Epochs | 100 |
| 学习率 | 0.003 (exp decay, rate=0.9999) |
| KL 权重 | 100.0, min=0.07 |
| 梯度裁剪 | 1.0 |
| 数据增强 | 旋转增强 (24 角度) |
| 高曲率过采样 | 开启 |

## 5. Results & Analysis

### 5.1 训练过程: 问题诊断与修复

首轮训练 (20 epochs) 暴露了从车载到路侧迁移的核心问题：

| 问题 | 根因 | 影响 | 修复 |
|------|------|------|------|
| PEDESTRIAN loss ≈ 10, 不收敛 | position std=1 (照搬 nuScenes), 实际数据 std≈80m | 输入值 ~80, 远超 RNN 有效范围 | std 改为 80/40 |
| 速度 max=42.4 m/s (理论上限 30) | 分量级 clipping: vx,vy 各 clip 到 30, 对角方向 30√2 | √2 倍放大 | 改为 norm-based clipping |
| 模型未充分收敛 | 20 epoch (4440 iter) 不足以完成 KL annealing | 预测分布质量低 | epoch 增至 100 |

**关键教训**: nuScenes 中 PEDESTRIAN position std=1 可以工作，是因为车载视角下行人坐标相对自车，范围仅 ~20m。路侧视角下行人位置使用全局坐标，std 高达 80m——这是视角差异导致的最直接的参数失配。

### 5.2 VEHICLE 预测结果 (Checkpoint 80, Test Set)

**总体指标** (5,827 个预测样本, ph=6 步/3 秒):

| 模式 | ADE (m) | FDE (m) | KDE NLL |
|------|---------|---------|---------|
| Most Likely (z-mode) | **0.619** | **1.300** | - |
| Full (2000 samples) | 0.903 | 1.829 | **-1.429** |

**与修复前对比**:

| 指标 | Epoch 20 (修复前) | Epoch 80 (修复后) | 改善 |
|------|-------------------|-------------------|------|
| ADE | 1.084 m | **0.619 m** | -42.9% |
| FDE | 2.020 m | **1.300 m** | -35.6% |
| KDE NLL | 1.685 | **-1.429** | -3.114 |

**按速度段分析**:

| 速度段 | 样本数 | ADE mean | ADE median | FDE mean |
|--------|--------|----------|------------|----------|
| 静止 (<0.5 m/s) | 1,241 (21%) | 0.084 | 0.021 | 0.134 |
| 低速 (0.5-2 m/s) | 327 (6%) | 0.216 | 0.141 | 0.437 |
| 中速 (2-5 m/s) | 466 (8%) | 0.419 | 0.301 | 0.826 |

### 5.4 VEHICLE vs PEDESTRIAN 对比

| 指标 | VEHICLE | PEDESTRIAN | 分析 |
|------|---------|------------|------|
| ML ADE | 0.619 m | 0.649 m | 接近，PEDESTRIAN 略高 |
| ML FDE | 1.300 m | 1.237 m | PEDESTRIAN 反而略优 |
| KDE NLL | -1.429 | 1.308 | PEDESTRIAN 概率建模质量较低 |

PEDESTRIAN 的 KDE NLL 明显高于 VEHICLE，说明概率分布建模不够精确。这可能是因为 PEDESTRIAN 类别混合了步行者 (~1-2 m/s) 和电瓶车/摩托车 (~5-15 m/s) 两种截然不同的运动模式，单一 SingleIntegrator 动力学模型难以同时精确建模两者的概率分布。

### 5.5 定性分析 (Case Study)

#### VEHICLE 代表性案例

| 类别 | ADE (m) | FDE (m) | 速度 | 场景类型 |
|------|---------|---------|------|---------|
| **Best** (最优) | 0.652 ± 0.027 | 1.371 ± 0.110 | 3.7 ± 2.2 m/s | turning, curved, straight |
| **Worst** (最差) | 20.490 ± 15.999 | 35.524 ± 25.948 | 14.7 ± 8.8 m/s | turning, straight |
| **Turning** (转弯) | 1.880 ± 0.006 | 3.609 ± 0.363 | 2.9 ± 1.4 m/s | turning |
| **High Speed** (>15 m/s) | 2.209 ± 0.002 | 4.345 ± 0.453 | 17.4 ± 1.7 m/s | straight |
| **Median** (中位数) | 1.994 ± 0.000 | 4.173 ± 0.344 | 8.8 ± 3.3 m/s | straight, turning |

**发现**:
- 最优 case 集中在低速转弯/弯道场景 (ADE < 0.7m)，轨迹变化平缓，模型预测精准
- 最差 case 出现在高速转弯场景 (ADE > 10m)，轨迹发生急剧方向变化，模型无法预见
- 高速直行场景 ADE ≈ 2.2m，对于 17 m/s (60 km/h) 速度下 3 秒预测，误差率约 4.3%

#### PEDESTRIAN 代表性案例

| 类别 | ADE (m) | FDE (m) | 速度 | 场景类型 |
|------|---------|---------|------|---------|
| **Best** (最优) | 0.187 ± 0.035 | 0.284 ± 0.035 | 0.4 m/s | stationary |
| **Worst** (最差) | 10.001 ± 2.861 | 15.683 ± 3.547 | 8.4 ± 1.5 m/s | turning |
| **Turning** (变向) | 1.216 ± 0.020 | 2.710 ± 0.378 | 1.8 ± 1.3 m/s | turning |
| **Fast** (>3 m/s) | 0.828 ± 0.001 | 1.519 ± 0.159 | 7.5 ± 0.7 m/s | straight |
| **Median** (中位数) | 0.784 ± 0.000 | 1.524 ± 0.288 | 5.8 ± 2.6 m/s | straight, curved |
| **Stationary** (静止) | 23.622 ± 10.510 | 32.122 ± 9.200 | 0.1 m/s | stationary |

**发现**:
- 行人最差 case 速度 8.4 m/s (约 30 km/h)，超出正常行人速度范围，很可能是被标注为 PEDESTRIAN 的电瓶车/非机动车，或跟踪 ID 跳变导致的异常轨迹
- 静止行人 worst case ADE 高达 23.6m：模型对速度接近零的目标预测出了大幅位移，说明模型未学好"保持静止"模式，这是一个 limitation
- 快速直行 (7.5 m/s) ADE ≈ 0.83m，预测质量良好

## 6. Safety Metrics (TTC / PET)

### 6.1 指标定义

基于模型预测轨迹计算两类交通冲突指标：

| 指标 | 全称 | 定义 | 意义 |
|------|------|------|------|
| **TTC** | Time-to-Collision | 两个 agent 按预测轨迹运动，首次碰撞的时间 | TTC 越小，碰撞风险越高 |
| **PET** | Post-Encroachment Time | 两个 agent 先后经过同一冲突点的时间差 | PET 越小，冲突越严重 |

**碰撞判定**: 基于 agent 尺寸自适应碰撞半径。VEHICLE 取 max(length, width)/2，PEDESTRIAN 默认 1.0m，双方半径之和为碰撞距离。

### 6.2 总体结果

基于 checkpoint 80 模型预测，对测试集 14 个场景的分析结果：

| 指标 | 值 |
|------|-----|
| 总交互对数 | 52,970 |
| 存在碰撞风险 (TTC < ∞) | 3,523 (6.7%) |
| 其中 TTC = 0 (已在碰撞半径内) | 2,578 (73.2% of 碰撞风险) |
| TTC > 0 (真正趋近碰撞) | 945 对 |
| 存在冲突点 (PET 有效) | 2,681 (5.1%) |

### 6.3 TTC 分布

| 阈值 | 交互对数 | 占总对数比例 |
|------|---------|------------|
| TTC < 1.0s | 2,737 | 5.17% |
| TTC < 2.0s | 3,055 | 5.77% |
| TTC < 3.0s | 3,368 | 6.36% |

对于 TTC > 0 的 945 对 (排除已在碰撞半径内的情况)：mean = 1.74s，median = 1.50s。

> **关于 TTC = 0**: 73.2% 的碰撞风险 case 在观测时刻已在碰撞半径内 (TTC=0)。这是路侧场景的正常现象——路口排队等红灯时，车辆前后间距通常 < 4m，小于 V-V 碰撞半径 (~4-5m)。这与车载视角数据集的特性不同：车载数据通常不包含大量静态密集排队场景。

### 6.4 PET 分布

| 阈值 | 冲突对数 | 占有效 PET 比例 |
|------|---------|---------------|
| PET < 1.0s | 1,164 | 43.4% |
| PET < 2.0s | 2,129 | 79.4% |
| PET < 3.0s | 2,561 | 95.5% |

PET 均值 1.16s，中位数 1.00s，最小值 0.50s (= dt，离散时间步的分辨率下限)。

### 6.5 按交互类型统计

| 交互类型 | 交互对数 | 碰撞风险对数 (占比) | 平均最小距离 |
|---------|---------|------------------|------------|
| VEHICLE-VEHICLE | 36,244 | 3,017 (8.3%) | 12.08 m |
| PEDESTRIAN-VEHICLE | 13,595 | 150 (1.1%) | 13.19 m |
| PEDESTRIAN-PEDESTRIAN | 3,131 | 356 (11.4%) | 9.42 m |

**分析**:
- **V-V** 碰撞风险占总碰撞的 85.6%，以跟车和排队场景为主，这与路口场景特征一致
- **P-V** 碰撞风险最低 (1.1%)，说明在本数据集中人车交互点较少，人车分离度较好
- **P-P** 碰撞比例最高 (11.4%)，因为行人活动区域集中、聚集密度高

### 6.6 预测 vs 真值对比

| 指标 | MAE mean | MAE median |
|------|----------|-----------|
| TTC | 0.13s | 0.00s |
| PET | 0.15s | 0.00s |

模型预测的 TTC/PET 与真值高度一致，误差中位数为 0，说明 **Trajectron++ 的轨迹预测质量足以支撑下游安全态势评估**。在多数交互场景中，模型预测轨迹得出的安全指标与真值轨迹完全一致。

## 7. Discussion

### 7.1 路侧 vs 车载视角的迁移经验

本实验证明了 Trajectron++ 从车载到路侧视角的迁移是可行的，但需要注意以下适配要点：

1. **标准化参数必须重新校准**: 车载视角下 PEDESTRIAN position std=1 可以工作 (相对自车坐标范围小)，但路侧全局坐标下 std 高达 80m，直接使用原参数会导致模型不收敛。这是迁移中最关键的一步。

2. **物理约束需要适配**: 原始的分量级 velocity clipping 在对角方向产生 √2 倍放大，改为 norm-based clipping 后数据更加物理合理。

3. **训练策略基本可复用**: batch size、学习率、KL annealing 等超参数无需大幅调整，仅需增加训练 epoch 即可。

### 7.2 路侧视角的独特发现

1. **TTC=0 的高占比**: 路侧视角覆盖整个路口，包括排队停车的密集车流，导致 73% 的碰撞风险 case 在观测时刻已在碰撞半径内。这一现象在车载数据集中很少出现——车载视角通常只关注前方运动中的目标。

2. **多类交互的全局视图**: 路侧视角同时观测 V-V、P-V、P-P 三类交互，提供了比车载视角更全面的交通安全态势评估。P-V 碰撞风险仅 1.1%，而 P-P 高达 11.4%，揭示了不同交互类型的风险差异。

3. **静止/低速目标占比高**: 路侧数据中 21% 的 VEHICLE 和 27% 的 PEDESTRIAN 样本速度 < 0.5 m/s，这在车载数据集中极为少见。模型对静止目标的预测 ADE 很低 (0.08m/0.19m)，但对部分静止 PEDESTRIAN 产生了异常大的预测偏移。

### 7.3 当前 Limitations

1. **PEDESTRIAN 类别混杂**: 将骑行者/电瓶车/摩托车合并到 PEDESTRIAN 导致类内运动模式差异大 (步行 ~1 m/s vs 电瓶车 ~10 m/s)，KDE NLL (1.308) 远高于 VEHICLE (-1.429)。未来可考虑引入第三类 `CYCLIST` 并设计专用动力学模型。

2. **静止行人预测偏移**: worst-case 静止行人 ADE 达 23.6m，模型对速度接近零的目标有时预测出不合理的大位移。可能原因：(a) 训练数据中运动样本占主导，模型偏向预测运动；(b) SingleIntegrator 模型缺乏"保持静止"的显式机制。

3. **异常速度样本**: PEDESTRIAN 中存在速度 > 8 m/s 的样本，可能来自标注错误或跟踪 ID 跳变。这些样本会拉高 worst-case 误差。

4. **时间分辨率**: dt=0.5s 限制了 PET 的最小值为 0.5s，对于需要更精细时间分辨率的安全评估 (如 PET < 0.5s 的极端冲突) 可能不够。

### 7.4 下一步工作

| 方向 | 说明 | 优先级 |
|------|------|--------|
| 数据清洗 | 过滤 PEDESTRIAN 中 speed > 5 m/s 的异常样本，分析是否为标注错误 | 高 |
| 类别细分 | 将骑行者/非机动车从 PEDESTRIAN 中分离，单独建模 | 中 |
| Checkpoint 100 评估 | 当前使用 checkpoint 80，最终 100 可能进一步改善 | 中 |
| 多场景泛化 | 在不同路口、不同时段的数据上验证模型泛化能力 | 中 |
| 与 baseline 对比 | 与线性外推 (CV/CA) 和其他模型 (Social-LSTM, AgentFormer) 比较 | 低 |
